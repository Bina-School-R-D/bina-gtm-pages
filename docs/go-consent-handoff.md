## Implemented local PostHog integration

The supplied banner source defines `getCkyConsent().categories.analytics` as a boolean. It dispatches CustomEvents on document: `cookieyes_banner_load` detail is the consent snapshot; `cookieyes_consent_update` detail contains accepted/rejected arrays. The gate reads the getter initially and after either event. Only literal `true` grants access. Missing, malformed or throwing APIs deny access. The no-banner automatic grant works even while user action is incomplete; there is no local geo policy.

The exact saved `preparation/posthog-array.js` has SHA256 `087e8d79202fd34df2381edfa028fed6850a7438139213d76a09edc3501c6b05`. Its CDN tail creates an unloaded instance without queued `_i` entries. The gate therefore inserts one async SDK script only after grant, without the old snippet or queued init. Its `onload` rechecks current CookieYes state before calling `init`. Grant then revoke during download leaves the arriving SDK uninitialized, including when prior PostHog opt-in is stored. A later grant can initialize that same loaded SDK. Failed downloads can retry on a later event.

After initialization, revocation calls the actual public `opt_out_capturing()` and `stopSessionRecording()` APIs. Source inspection shows these update stored consent/persistence and disable recording. Regrant calls `opt_in_capturing()` and `startSessionRecording()` without override arguments, retaining server replay sampling/triggers. Repeated events do not repeat loading, initialization or transitions. Project, public token, API host, defaults, bot/host exclusions and the GTM loader are preserved. PostHog waits for the shared GTM CookieYes getter, so consent resolution can delay short-visit capture.

`scripts/check-posthog-consent.mjs` exercises the actual gate with deterministic SDK doubles. These tests cover unknown/false/string consent, getter failure, automatic and returning grant, repeated events, revoke/regrant, download failure and delayed grant/revoke races. Source findings support the design, but doubles cannot prove SDK ordering. The parent ran `preparation/parent-vendor-final/check-posthog-vendor.mjs` under `unshare --net` using the installed Chromium headless shell, exact saved SDK, fictional token, fresh temporary profile, restrictive CSP and blocked transport. All 18 assertions passed, including stored prior opt-in/opt-out and the delayed SDK race; two intercepted granted transport attempts provided a positive control, not delivery. The parent copy changes only the browser executable path from the author helper. Historical author EPERM and parent full-Chrome timeout receipts are retained separately. Remote configuration and rrweb assets are blocked in that fixture, so active recorder frames remain a later controlled-preview check.
